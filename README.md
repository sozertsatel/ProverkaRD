# РД Контроль

Настольная программа для сверки рабочей документации одного этапа. Сопоставляет четыре источника:

- акт сдачи-приёмки РД (DOCX);
- ведомость ВЭРД (XLSX, лист «База»);
- ведомость ВЭСР (XLSX, лист «ВЭ»);
- комплекты РД (PDF или DOCX) и отсоединённую подпись `<файл>.sig`.

Расхождение смысла, цифр, номеров ПК или пропущенное «ПК» помечается как **Критично**. Совпадение после нормализации (пробелы, невидимые символы, похожая латиница, регистр, точка, «ПК 5859» и «ПК5859») и опечатка в одну-две буквы — **Ошибка оформления**. Фамилия из тома, которой нет в `.sig`, — критично; лишние люди в подписи не показываются. Подпись сверяется с байтами файла всегда, даже когда имя `.sig` точное. Если этот файл подписи не покрывает документ — критично «Подпись не относится к файлу»; подходящая подпись с другим именем указывается рядом. Если точного имени нет, а другая подпись в папке покрывает файл, это ошибка оформления имени. Подпись ГОСТ Р 34.10-2012 проверяется криптографически по сертификату внутри `.sig`. Цепочка до доверенного корня не строится. Из сертификата читаются SN, G и CN. Если сертификат не действовал в момент подписания — критично. Нет времени подписания — предупреждение.

Версия сборки — 0.1.9. Она стоит в заголовке окна, в первой строке каждого листа отчёта и в колонтитуле. Файл программы — `ProverkaRD.exe`. История изменений — в `CHANGELOG.md` и в окне «О программе». Ставка НДС задаётся в «Настройках» (по умолчанию 22%). Проверка начинается только когда загружены и ВЭРД, и ВЭСР. До проверки акты и комплекты собраны в одно дерево: у акта число PDF, у файла — есть ли подпись рядом, файлы без акта лежат отдельной группой. После проверки окно показывает итог одной строкой и ниже — сколько актов, комплектов, PDF, подписей и посторонних файлов загружено. Суммы считаются в decimal и округляются до копейки. В «Пропусках» только строки ведомостей, которые относятся к элементам актов; пустая сумма найденной строки ВЭСР — замечание по элементу. Журнал запуска открывается из «Настроек». Лист «Опись комплекта» — опись для печати: номер только у комплектов, посторонние файлы, в том числе DOCX, ниже итога, статус подписи окрашен. Во время проверки верхняя полоса показывает этап и прошедшее время; загрузка актов и комплектов — короткая полоса в своей строке. Номер этапа для имени отчёта берётся из имени ВЭРД, из текста акта, из префикса элемента или из шифра.

Ведомости ВЭРД и ВЭСР можно перетащить в зоны под шапкой. Нужен файл .xlsx; имя выбранного файла остаётся рядом с кнопкой.

При запуске программа молча спрашивает последний релиз `sozertsatel/ProverkaRD`, если в настройках включена проверка обновлений. Кнопка «Проверить обновления» делает то же самое. Если тег `vX.Y.Z` новее установленной версии, показывается текст релиза и кнопки «Обновить» и «Позже». Та же или более старая версия (в том числе `v0.1.8` рядом с `0.1.8`, `0.1.8.0` и `0.1.8+hash`) даёт окно «У вас актуальная версия», файл не скачивается. «Обновить» скачивает `ProverkaRD.exe`, сверяет размер и `ProverkaRD.exe.sha256`, заменяет текущий файл и перезапускает программу. Кнопка «Принудительное обновление» при той же версии показывает «У вас актуальная версия (X.Y.Z)» и скачивает файл только после «Всё равно переустановить». Если записать файл в папку нельзя, замена ставится в очередь до закрытия программы. Без сети тихая проверка ничего не показывает; кнопка сообщает об ошибке и открывает страницу релиза. Закрытый репозиторий без входа отвечает 404: это «проверить не удалось».

## Запуск

Нужен SDK .NET 8.

```bash
dotnet run --project src/ProverkaRD.App
```

Сборка одного exe для Windows (x64, со средой выполнения внутри файла):

```bash
dotnet publish src/ProverkaRD.App -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true \
  -p:IncludeNativeLibrariesForSelfExtract=true \
  -p:EnableCompressionInSingleFile=true
```

Готовый файл — один `ProverkaRD.exe`. Сжатие внутри пакета не меняет состав: среда выполнения и нативные библиотеки по-прежнему внутри файла и распаковываются при запуске.

Проверка без окна, с записью отчёта:

```bash
dotnet run --project src/ProverkaRD.App -- --check \
  --verd samples/etap7.xlsx \
  --vesr samples/vesr.xlsx \
  --acts samples/akty \
  --rds samples/rd \
  --out отчёт.xlsx
```

## Как пользоваться

1. «Загрузить ВЭРД» и «Загрузить ВЭСР» — или перетащите xlsx в зону рядом. В строке остаётся имя файла.
2. Слева — акты (файлы, папка или перетаскивание).
3. Справа — комплекты РД тем же способом. Файл `.sig` рядом подхватывается сам.
4. «Проверить» заполняет таблицы, если выбраны обе ведомости. Если какой-то нет, в плашке будет «Не загружена ВЭРД» или «Не загружена ВЭСР», и сверка не начнётся. Красная строка — критично, жёлтая — оформление, оранжевая — предупреждение, зелёная — совпадает. Списки актов и комплектов после проверки сворачиваются в одну строку.
5. «Выгрузить отчёт (Excel)» пишет книгу из трёх листов: «Сводка», «Комплекты», «Замечания». В первой строке листа и в колонтитуле — «РД Контроль» и версия программы.
6. «Проверить обновления» в окне «О программе» скачивает новую сборку, если она есть. Та же версия — «У вас актуальная версия», без скачивания. «Принудительное обновление» при той же версии показывает «У вас актуальная версия (X.Y.Z)» и качает файл только по кнопке «Всё равно переустановить».
